# Obsidian 对话归档规划

日期：2026-10-10。状态：用户已授权执行计划；1.8.0 已实现、安装并完成下方记录范围内的真实验收。术语见 [CONTEXT.md](CONTEXT.md)。

## 用户已提出的需求

- 在截图所示回答操作栏增加保存到 Obsidian 的按钮。
- 使用 OpenAI 兼容 API 为对话推荐目标文件夹并生成标签。
- 保存前提供预览，允许修改目标文件夹和标签。
- 在脚本配置面板维护 Obsidian 库路径和 AI 连接配置。
- 用户提供的本地 API base URL 为 `http://127.0.0.1:8045/v1`。凭证已在会话中提供；本文及版本控制文件不保存密钥。执行阶段已验证指定模型与实际分类请求。

## 已确认的决策

- Q1：每次仅归档点击按钮对应的一问一答。
- Q2：首版覆盖 Chat、Work 和 Codex Cloud，分别验证按钮位置和内容提取。
- Q3：正文保留原始问答，AI 仅建议标题、目标文件夹和标签。
- Q4：AI 分类可参考目标库的目录树和已有标签；不包含其他笔记标题、属性或正文。
- Q5：首版目标库为 `E:\Obsidian`，用户于 2026-10-10 确认。路径维护在本机配置中，单库范围由 Q13 确定。
- Q6：首版复用 Obsidian Local REST API 插件，不新增独立本地后台服务。Obsidian 未运行或 API 不可用时，在网页右上角弹出错误消息。架构取舍见 [ADR 0008](../adr/0008-obsidian-rest-api.md)。
- Q7：保存用户问题与所选最终回答，保留代码、公式、表格、引用链接；附件仅保留名称与来源，不下载二进制，不收录工具执行日志。
- Q8：同一问答重复保存直接覆盖已有归档笔记，包括已被用户手动修改的内容；不增加冲突处理或二次覆盖确认。用户仍通过保存预览中的保存按钮触发写入。
- Q9：AI 优先复用目录和标签，允许建议新项；预览标明新项，确认保存后才创建。
- Q10：AI 分类失败时显示具体错误，保留预览，允许用户手动填写后保存。
- Q11：保存预览不显示问答正文，标题、目标文件夹和标签可编辑，显示最终文件路径。
- Q12：回答生成期间归档按钮保持显示但不可用，回答完成后启用。
- Q13：首版只操作单个库，直接与 Local REST API for Obsidian 插件通信。不实现多库列表、切换库或独立后台服务；库路径配置表示目标库，不具备切换 REST 插件所在库的能力。
- Q14：使用用户提供的 OpenAI 兼容服务，模型 ID 为 `gemini-3.8-flash-high`；不增加模型列表选择流程。执行阶段已确认服务接受该模型并返回分类结果。
- Q15：再次保存时若标题或目录变化，同步重命名或移动归档；确认新路径写入成功后移除旧路径文件，不遗留副本。
- Q16：重新生成的回答按新回答处理，独立归档；重复保存同一回答仍按 Q8 直接覆盖。
- Q17：不增加专门的超长内容检测、截断、分块或降级策略；该要求不等于认定上游不存在长度限制。普通 API 请求失败仍按 Q10 已确认的通用错误行为处理。

## 最终确认

- 产品问题 Q1～Q17 已回答，无剩余模型名称澄清。
- 用户已明确要求“执行计划”，实施已授权。当前实际验证结果以[验收记录](../../userscripts/chatgpt-queue/VALIDATION.md)为准。

## 实施方案

1. 为 Chat、Work、Codex 的回答操作栏增加归档入口。复用模式识别，独立提取所点击回答及对应问题，避免将队列回执文本当作保真导出。
2. 点击时冻结该问答快照；确认回答已结束，读取目标库目录和标签，调用所配置的 AI 服务产生标题、库内文件夹和标签建议。
3. 使用网页实际主题与 Accent color 呈现元信息预览。用户编辑后保存；正文不显示、不经 AI 改写。取消预览不写入笔记。
4. 生成 Markdown 原始问答及来源属性，通过 Obsidian REST API 写入。以来源会话和回答身份区分记录，区分重新生成版本；文件名建议使用标题及稳定短标识，避免不同回答同名覆盖。
5. 保存成功后才提示成功、更新本地归档映射。标题或目录改变时先写新路径，再删除旧路径；错误显示具体阶段，不把部分成功误报为迁移完成。
6. 在现有脚本设置中维护单库路径、Obsidian REST 连接信息、OpenAI 兼容连接信息及模型 ID。凭证存于用户脚本本地配置，不进入源码、笔记或诊断输出。

归档模块已作为独立源码加入脚本构建，API 调用使用 `GM_xmlhttpRequest`；目录和标签响应契约经过已装 REST 版本的真实接口核实。产品行为以已确认决策为准。

## 验收范围

- 三种模式均在指定的真实页面验收：按钮位置、生成中禁用、问答配对、重新生成版本识别及原生主题。
- 保存后读取实际生成文件核对代码、公式、表格、引用及来源属性；预览无正文，编辑的标题、目录、标签实际生效。
- 同一回答直接覆盖，重新生成回答独立归档，改名/换目录后旧路径按约定移除。
- Obsidian API 不可用时右上角报错，AI 分类失败允许手动保存；取消操作不写笔记，保存失败不显示成功。
- 队列既有操作与配置保持可用。本地测试、API 验证和真实页面验收分别记录。

## 实施边界

实现复用 `src/browser.js` 中的 `QueueSettings`、主题同步和模式识别。`ChatGPTAdapter.messages()` 用于定位已渲染消息；独立归档模块负责问答配对与 Markdown 转换。构建已授予 `GM_xmlhttpRequest` 和本地 API 主机权限；库内文件写入通过 Obsidian REST 服务完成。

规划阶段只读检查发现两个已注册且目录存在的 Obsidian 库，其中一个安装 `obsidian-local-rest-api`（manifest 名称 Local REST API with MCP，版本 5.1.0）。当时未观察到进程；执行阶段用户打开目标库并配置连接，真实 API 已验证。插件文件存在不能代替服务连通性验证。

规划阶段的未认证 `/v1/models` 请求返回 HTTP 401；执行阶段认证请求返回 200，指定模型分类通过。已装 Obsidian 插件支持目录列举、标签索引和原始 Markdown 写入；服务随插件卸载而关闭。目录列表可能不包含空文件夹，预览允许手动输入新增路径。

执行阶段已安装 1.8.0，指定模型与 Obsidian API 的合成笔记测试通过。用户在原生 Firefox 信任插件自己的 HTTPS 证书后，Chat、Work 和当前 Codex 页面均完成分类、编辑和保存；Chat 覆盖与迁移通过，专用合成和浏览器验收笔记已清理，用户实际归档保留。未读取其他笔记正文或关闭 TLS 校验。生成中禁用和重新生成版本通过回归测试，未在浏览器触发新生成；详细边界见[验收记录](../../userscripts/chatgpt-queue/VALIDATION.md)。
