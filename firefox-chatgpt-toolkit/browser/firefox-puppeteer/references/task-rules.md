# Puppeteer 任务规范

## 连接与范围

- 使用本模块的锁定 `puppeteer-core`，通过 `connect()` 连接已有原生 Firefox；`protocol: 'webDriverBiDi'`、`defaultViewport: null`、`acceptInsecureCerts: false`。一般 DOM 检查设置 `networkEnabled: false`。
- 使用 Nightly Remote Control 的运行时入口；进程核对通过后连接，页面实际 webdriver 必须为 false。保留 Firefox 原生连接确认和网页对话框，`unhandledPromptBehavior: 'ignore'`；握手最多等待 60 秒，不自动重试确认或接管其他会话。
- 连接端点限 `ws://127.0.0.1:<port>/session`。连接库会发现浏览器级上下文及订阅部分事件，目标筛选不是浏览器安全隔离；不收集或输出无关页面正文、网络内容与凭据。
- 从已有页面按完整 URL 唯一匹配，再核对标题。每次页面操作内部核对 `location.href` 和 `document.title`，处理导航与异步等待带来的竞争。
- 连接失败、重复目标或会话已占用时报告具体阶段。不会通过关闭他人的调试会话、启动替代浏览器或切换用户页面修复。

## 后台操作

- 用户脚本安装/更新遵循 [工作流](userscript-workflow.md)，优先油猴原生更新机制。Firefox 明确拒绝的扩展页导航不能改用其他协议或页面脚本规避。安装确认保留给用户；不要以发布或下载成功冒充安装完成。

- 保持前台窗口、可见标签、窗口尺寸、剪贴板、草稿和队列。已有页面使用 `evaluate`/定位器读取，按操作验证后台行为。
- `launch()`、`bringToFront()`、修改窗口尺寸、系统键鼠、Console 粘贴及重启浏览器不进入日常验收脚本。结束用 `disconnect()`，不调用 `browser.close()` 或 `page.close()`。
- Puppeteer 的点击/输入会走浏览器协议；不能仅凭“不是系统鼠标”就认定不抢焦点。新增输入操作先验证前后台状态。页面 DOM 合成事件单独标为合成事件证据。
- 只读工具不调用页面点击、提交、存储写入或刷新。修改目标页面前确认用户已授权该具体业务操作、页面无生成任务、草稿和队列已得到保留。
- 超时后先观察结果，只有确认未执行且操作允许重试时才重试。队列发送与 Obsidian 写入不得盲目重放。

## 证据与完成条件

1. 安装验收：锁定依赖可导入、Node 满足 engines、模块测试和项目统一验证通过。
2. 接入验收：真实原生 Firefox BiDi 握手成功，读取明确目标，断开后浏览器继续运行。
3. 不干扰验收：操作前后以及期间观察前台 HWND 和可见标签；出现变化须区分用户活动与工具引起，不能通过强行恢复来掩盖抢焦点。不得修改剪贴板。
4. 业务验收：按真实回执或保存结果断言；按钮存在不等于可见，执行点击不等于消息送达，临时注入不等于油猴安装成功。
5. 视觉验收：遵循 AgentCapture skill，实际查看图片。未选中标签无法用当前窗口截图证明；必要时安排独立验收窗口的方案并先汇报，不能替用户切换标签。

日志默认脱敏；原始证据、会话网址和临时配置保存在项目 `.local/`。报告区分 offline、endpoint、browser、visual 四类证据，分别标明是否执行。

`environment` 与 `inspect` 使用 Windows 观察器记录 HWND、标签运行时 ID、窗口矩形和剪贴板序号；不采集其他标签的正文、地址或标题。采样不足或状态变化时退出 2，结论为 inconclusive。页面草稿用指纹比较，报告仍属于私有证据。观察器依赖 PowerShell 7；Node 调用 Windows PowerShell 5.1 曾出现无输出退出 2，不能用缺少观察结果代替通过。

## 失败后的推进

没有端口：继续依赖/本地检查，准备首次启用步骤，保留真实网页验收待办。握手或 evaluate 失败：先检查固定版本与 Firefox 支持范围、会话占用和协议错误；做最小只读复现。确认为上游缺口时优先升级到已核查版本或复用其他成熟客户端，修订方案并记录原因。不得因一次失败回退到干扰桌面的操作。
